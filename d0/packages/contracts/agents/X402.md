# X402 — the cabal's intel gate

Companion to CABAL.md.*

The cabal's product is intelligence. Everything it sells is already true on chain —
what buyers pay for is curation, freshness, and voice: the watchmen's ledger cleaned
and snapshotted, the private chronicle (which never runs on the public terminals),
and the desk's own tape with cost basis. The public terminals (/obsidian,

## Drop format (sealed by `agents/intel-drops.mjs`)

```json
{
  "kind": "cabal-intel-drop",
  "version": 1,
  "product": "desk-tape",
  "id": "<sha256 of {product, payload}>",
  "at": "2026-10-19T00:00:00.000Z",
  "payload": { "...": "product data" },
  "issuer": "0x007783A0efc51953ce21C5B1E204bdf9FA08C27a",
  "signature": "<sovereign EIP-191 signature over id>"
}
```

- **Authenticity**: `signature` recovers to the sovereign — the same address the
  public terminals show as the corporation's seat. A drop that does not verify
  against the sovereign is counterfeit, full stop.
- **Freshness**: `at` is the seal time; `id` is content-addressed, so identical
  payloads collapse to the same drop and buyers can dedupe.
- Unsigned drops (`signature: null`) are test artifacts and MUST NOT be served.

The catalog `agents/drops/manifest.json` describes every product, its price, its
latest drop id/file, and the payment instruction:

```json
{
  "kind": "cabal-intel-catalog",
  "payment": {
    "chain": "quai-mainnet-cyprus-1", "chainId": 9,
    "token": { "symbol": "Q0", "address": "0x00325150094E51107a931980Fdfc3bB1a4C48379" },
    "to": "0x0064AD45B58474d24F3e96d1d513E1c24fBFC912",
    "proof": "quai_getTransactionReceipt — ERC-20 Transfer to the vault, log-verified"
  },
  "products": [ ... ]
}
```

## The 402 flow (server contract)

Quai has no x402 facilitator today, so the gate self-verifies — any small server
(VPS, edge worker, the suite's existing x402 plumbing) can implement it:

1. `GET /intel/<product>` → server answers `402 Payment Required` with the
   manifest's payment block for that product (amount, token, vault address).
2. Buyer transfers ≥ price Q0 to the vault on Cyprus-1, then retries with
   `X-PAYMENT: <txHash>`.
3. Server fetches `quai_getTransactionReceipt(txHash)`, requires status 1, and
   scans logs for an ERC-20 `Transfer` from the token contract with `to == vault`
   and `value >= price`. The payment must be fresh — block timestamp within 72h —
   so an old donation can never be retro-claimed as a purchase. The tx hash is
   then burned: one hash, one drop (server keeps a claimed set; reuse gets `402`
   again).
4. Server returns the drop JSON. Payment already feeds the desk — the vault IS
   the trading entity, so every sale is treasury inflow the longevity strategy
   then manages.

The reference implementation is `agents/x402-gate.mjs` — a zero-dependency Node
server. Run it anywhere that can read `agents/drops/`:
`node agents/x402-gate.mjs --port 8402`. Verified end-to-end on mainnet:
valid purchase served, replay rejected, underpayment rejected.

## Hard rules

- The gate never sells what the chronicle does not have. If an organ is silent,
  its product goes stale visibly (`at` ages) — the catalog does not lie about
  freshness. Reputation is the only moat a secret cabal has.
- The free terminals are never paywalled, and drops never contain keys,
  passwords, or sybil internals — the payload is intelligence, never access.
- A buyer may republish a drop. The signature still points at us. Piracy is
  distribution with our name on it.
